# Hollow 通用包协作规则

## 适用范围

- 本文件适用于 `pkg` 及其子目录，并继承仓库根目录的规则。

## 收录边界

- `pkg` 只接收可被多个独立项目复用的通用能力。
- 禁止引入具体业务模型、业务错误码、业务配置或对 `life-core` 等业务项目的依赖。
- 新增包统一使用 `h*` 命名，并保持职责单一、依赖最小。

## API 设计

- 公共 API 应保持最小且清晰，不为单一调用场景提前抽象或增加未经需求验证的扩展点。
- 公共类型、函数和配置项必须说明用途、边界和默认行为，并考虑已有调用方的兼容性。
- 明确 `context.Context` 的传递、错误传播、资源生命周期和并发安全边界。
- 避免不必要的全局可变状态、隐式初始化和重型第三方依赖。

## 测试与文档

- 新增或变更公共能力必须配套单元测试，并为使用方式补充 README、包文档或示例。
- 并发组件必须覆盖启动、停止、重复调用和异常路径，并执行 `go test -race`。
- 测试优先验证公开行为，避免依赖无法保证的内部实现细节。
