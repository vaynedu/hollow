# Hollow CLI 协作规则

## 适用范围

- 本文件适用于 `cmd/hollow_cli` 及其子目录，并继承仓库根目录的规则。

## CLI 定位

- CLI 保持简单，负责生成可独立运行的通用 Web 服务目录骨架。
- 当前核心命令是 `init`；未经明确需求确认，不增加命令、参数或组件选择能力。
- 目录骨架由 CLI 创建；Proto 相关 Go 代码和 HTTP 层由生成项目中的 `make proto` 生成，不在 CLI 中重复实现代码生成逻辑。

## 模板约束

- CLI 模板属于正式公共接口，目录结构、默认配置、Makefile 和生成规则的变更都必须考虑兼容性。
- 自动生成文件与手写文件必须分离；手写的 control、service、dao、model 等业务文件只在首次创建时生成，不得被后续生成覆盖。
- 默认依赖已发布的 Hollow Go Module；只有用户显式指定本地 Hollow 路径时，才允许生成 `replace` 配置。

## 测试与验证

- 修改生成器或模板时，必须补充或更新生成器测试。
- 必须在临时目录实际执行一次项目生成，并验证生成项目的目录结构、`make proto`、编译和测试。
- 验证过程不得污染仓库或覆盖已有项目。
